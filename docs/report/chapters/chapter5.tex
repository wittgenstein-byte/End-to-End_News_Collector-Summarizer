\section{สรุปผลการดำเนินโครงงาน}
% -----------------------------------------------------------

โครงงานระบบรวบรวมและสังเคราะห์ประเด็นข่าวภาษาไทยอัตโนมัติ (End-to-End News Collector and Summarizer) ได้ดำเนินการศึกษา วิเคราะห์ ออกแบบ พัฒนา และทดสอบตามวัตถุประสงค์และขอบเขตที่กำหนดไว้ โดยระบบสามารถดึงข้อมูลข่าวสารจากสำนักข่าวไทยชั้นนำ 14 แห่ง สกัดเนื้อหาบทความ ทำความสะอาดข้อความ และจำแนก 9 หมวดหมู่ข่าวด้วยสถาปัตยกรรม 3-Tier Cascade Classifier สรุปใจความสำคัญและวิเคราะห์อารมณ์ด้วยโมเดลภาษาขนาดใหญ่ ระบุและจัดกลุ่มประเด็นข่าวออนไลน์ 2 ชั้นแบบคงทน (Two-Band Persistent Story Identification) จัดอันดับกระแสข่าวสาร 6 มิติเชิงสถิติแบบ Zero-LLM เชื่อมโยงเส้นเรื่องมหาภาค สังเคราะห์แฟ้มไทม์ไลน์ และนำเสนอผ่านเว็บแอปพลิเคชัน Bento Hub SPA ที่รองรับการอัปเดตข้อมูลสดสองทิศทางผ่าน WebSocket ผลการดำเนินงานเมื่อเปรียบเทียบกับวัตถุประสงค์ของโครงงานสรุปได้ดังตารางที่~\ref{tab_obj_result}

สำหรับการประเมินความพึงพอใจของผู้ใช้งาน คณะผู้จัดทำได้ดำเนินการเก็บรวบรวมข้อมูลจากกลุ่มตัวอย่างผู้ใช้งานจริงที่ได้ทดลองใช้งานระบบบนเว็บแอปพลิเคชันจริง (\url{https://e2enews.wittensky.com}) จำนวน 9 คน โดยผู้ตอบแบบสอบถามประกอบด้วย นักเรียนและนักศึกษา จำนวน 7 คน (ร้อยละ 77.8) และกลุ่มวัยทำงาน ข้าราชการ หรือพนักงานรัฐวิสาหกิจ จำนวน 2 คน (ร้อยละ 22.2) ซึ่งทุกคนมีพฤติกรรมการติดตามข่าวสารผ่านสื่อสังคมออนไลน์เป็นหลัก (Facebook, X หรือ Twitter, TikTok, Reddit) โดยมีผู้ติดตามผ่านสื่อดั้งเดิมและเว็บไซต์สำนักข่าวโดยตรงร่วมด้วยคิดเป็นร้อยละ 11.1

ผู้ใช้งานได้ประเมินผลผ่านแบบสอบถามประเมินความพึงพอใจและประสิทธิภาพการใช้งานระบบตามภาคผนวก ค ทั้งในมิติด้านฟังก์ชันการทำงานหลัก (Core Features Evaluation) ครอบคลุม 6 ด้านสำคัญ มิติด้านการออกแบบและประสบการณ์การอ่าน (Design and Reading Experience) และความพึงพอใจโดยรวมต่อระบบ (Overall Platform Satisfaction) โดยผลการคำนวณค่าเฉลี่ยเลขคณิต ($\bar{x}$) และส่วนเบี่ยงเบนมาตรฐาน ($\text{S.D.}$) ตามสมการที่~\eqref{eq_mean} และ~\eqref{eq_std} สรุปได้ดังตารางที่~\ref{tab_satisfaction_survey}

จากตารางที่~\ref{tab_satisfaction_survey} ผลการประเมินความพึงพอใจของผู้ใช้งานจริงในภาพรวมอยู่ในระดับดีมาก โดยมีค่าเฉลี่ยรวมทุกรายการประเมินเท่ากับ 4.86 ($\text{S.D.} = 0.42$) เมื่อพิจารณารายด้านพบข้อค้นพบสำคัญดังนี้

ประการแรก ด้านฟังก์ชันการทำงานหลัก ได้รับการประเมินในระดับดีมากทุกรายการ โดยมีถึง 4 ด้านที่ได้รับคะแนนเต็ม 5.00 ($\text{S.D.} = 0.00$) จากผู้ตอบแบบสอบถามทุกคน ได้แก่ ความหลากหลายของสำนักข่าว 14 แหล่ง, คุณภาพการสรุปข่าวด้วยปัญญาประดิษฐ์ที่กระชับตรงประเด็นและไม่บิดเบือนข้อเท็จจริง, ความสดใหม่ของข้อมูลแบบเรียลไทม์ และระบบพรีวิวบทความที่ตัดสคริปต์อันตรายพร้อมลิงก์ไปยังต้นฉบับอย่างปลอดภัย ส่วนความเร็วในการสรุปข่าวด้วย AI ได้รับคะแนนเฉลี่ย 4.78 ($\text{S.D.} = 0.44$) และความแม่นยำในการจัดหมวดหมู่ข่าว 9 หมวดหมู่ได้รับคะแนนเฉลี่ย 4.67 ($\text{S.D.} = 0.71$)

ประการที่สอง เมื่อสำรวจฟังก์ชันการทำงานที่ผู้ใช้งานชื่นชอบหรือเห็นว่ามีประโยชน์มากที่สุด พบว่า ร้อยละ 55.6 ของผู้ใช้งาน ($n = 5$) เลือกฟังก์ชันปุ่มสรุป AI ทันทีในบทความข่าวเป็นฟังก์ชันที่ชื่นชอบที่สุด รองลงมาคือฟังก์ชัน AI ร้อยเรียงเรื่องราวจากหลายสำนักข่าวแบบ Storyline คิดเป็นร้อยละ 33.3 ($n = 3$) และการรวม 14 สำนักข่าวชั้นนำของไทยไว้ในแพลตฟอร์มเดียวคิดเป็นร้อยละ 11.1 ($n = 1$) นอกจากนี้ ในมิติการแนะนำบอกต่อเพื่อนร่วมงานหรือบุคคลรอบข้าง (Net Promoter Score บนสเกล 0 ถึง 7 คะแนน) ระบบได้รับคะแนนเฉลี่ยสูงถึง 6.33 คะแนน ($\text{S.D.} = 0.87$) โดยมีผู้ให้คะแนนระดับสูงสุด 7 คะแนนเต็ม คิดเป็นร้อยละ 55.6 แสดงถึงความเชื่อมั่นและการยอมรับในระดับสูงมาก

ประการที่สาม จากการวิเคราะห์ความคิดเห็นและข้อเสนอแนะเชิงคุณภาพ (Qualitative Feedback) ของผู้ใช้งานจริง สามารถจำแนกประเด็นปัญหาและข้อเสนอแนะที่ได้รับดังนี้
\begin{enumerate}
    \item \textbf{การตอบสนองบนอุปกรณ์เคลื่อนที่} ผู้ใช้งานบางท่านสะท้อนว่าการแสดงผลบนสมาร์ตโฟนในบางปุ่มยังไม่ Responsive เท่าที่ควร ซึ่งคณะผู้จัดทำได้นำข้อคิดเห็นนี้ไปปรับปรุงเลย์เอาต์ Bento Hub และกำหนดขนาดปุ่มสัมผัส (Touch Targets) ให้สอดคล้องกับขนาดหน้าจอมือถือ
    \item \textbf{แบบอักษรและการอ่าน} ผู้ใช้งานเสนอแนะให้ปรับแต่งแบบอักษรภาษาไทยให้มีความทันสมัยและอ่านง่ายยิ่งขึ้นสำหรับกลุ่มผู้ใช้งานคนรุ่นใหม่
    \item \textbf{ความลื่นไหลของระบบ} มีข้อสังเกตเรื่องความเสถียรในบางหน้าจอที่มีการประมวลผลข้อมูลพร้อมกัน ซึ่งคณะผู้จัดทำได้แก้ไขด้วยระบบแคชระดับ L1 ในหน่วยความจำ และกลไกป้องกัน Cache Stampede ด้วย Single-Flight Mutex Locking
    \item \textbf{หมวดหมู่ข่าวสารเพิ่มเติม} ผู้ใช้งานมีความต้องการให้ระบบเพิ่มการติดตามข่าวสารเศรษฐกิจแบบเรียลไทม์เพิ่มเติม
\end{enumerate}

\section{ข้อจำกัดของระบบ}
% -----------------------------------------------------------

จากการพัฒนาและทดสอบระบบจริง คณะผู้จัดทำได้สรุปข้อจำกัดของระบบออกเป็น 2 ด้านหลัก ดังนี้

\subsection{ข้อจำกัดด้านการทำงาน}

\begin{enumerate}
    \item \textbf{การเปลี่ยนแปลงโครงสร้างหน้าเว็บต้นทาง (DOM Mutation)}\\*
    เว็บไซต์ของสำนักข่าวออนไลน์อาจมีการปรับปรุงรูปแบบและโครงสร้างเอกสาร HTML หรือ CSS Selector ซึ่งอาจส่งผลให้ตัวแยกวิเคราะห์ (Parser) สกัดเนื้อหาบทความได้ไม่ครบถ้วน จนกว่าจะได้รับการปรับปรุงการตั้งค่าตัวสกัดให้ตรงกับโครงสร้างใหม่
    \item \textbf{การพึ่งพาบริการโมเดลภาษาขนาดใหญ่ภายนอก (External LLM Dependency)}\\*
    การสังเคราะห์เนื้อหาข่าวและการวิเคราะห์อารมณ์พึ่งพาการเชื่อมต่อ KKU Gen.AI API ซึ่งในกรณีที่เครือข่ายภายนอกขัดข้องหรือโควตาการเรียกใช้งานต่อนาทีเต็ม ระบบจะต้องสลับไปแสดงผลข้อความสรุปสำรองเชิงฮิวริสติก (Heuristic Fallback) โดยอัตโนมัติ
    \item \textbf{ขอบเขตของโมเดลการรู้จำชื่อเฉพาะ (NER Scope)}\\*
    โมเดลสกัดเอนทิตีภาษาไทย \texttt{thainer-v2} ถูกฝึกสอนจากคลังข้อมูลในอดีต ทำให้กรณีที่มีชื่อบุคคล สถานที่ หรือศัพท์สแลงเฉพาะกิจเกิดใหม่ในกระแสข่าวปัจจุบัน โมเดลอาจยังไม่สามารถรู้จำชื่อเฉพาะเหล่านั้นได้อย่างครบถ้วน
    \item \textbf{การประมวลผลเฉพาะข่าวภาษาไทย}\\*
    ระบบได้รับการออกแบบและฝึกสอนโมเดลเพื่อรองรับการประมวลผลภาษาไทยเป็นหลัก จึงยังไม่สามารถรวมกลุ่มบทความข่าวภาษาต่างประเทศเข้ากับประเด็นข่าวภาษาไทยในเหตุการณ์เดียวกันได้
\end{enumerate}

\subsection{ข้อจำกัดด้านฮาร์ดแวร์และสภาพแวดล้อม}

\begin{enumerate}
    \item \textbf{การใช้ทรัพยากรของ Playwright Headless Browser}\\*
    การเปิดใช้อินสแตนซ์ของเบราว์เซอร์ Chromium เพื่อสกัดหน้าเว็บที่เรนเดอร์ด้วย JavaScript และผ่านด่านตรวจบอต จำเป็นต้องใช้หน่วยความจำหลัก RAM และรอบเวลาประมวลผลของ CPU สูงกว่าคำขอ HTTP ปกติ ทำให้ระบบต้องจำกัดจำนวนการเปิดหน้าต่างเบราว์เซอร์พร้อมกันเพื่อรักษาเสถียรภาพของเครื่องแม่ข่าย
    \item \textbf{การประมวลผลโมเดล Transformer บนหน่วยประมวลผลกลาง (CPU-only)}\\*
    บนเครื่องแม่ข่ายคลาวด์ที่ไม่มีการติดตั้งหน่วยประมวลผลกราฟิก (GPU) การสร้างเวกเตอร์ความหมาย 768 มิติด้วยโมเดล WangchanBERTa จะใช้เวลาประมวลผลเฉลี่ยประมาณ 48 มิลลิวินาทีต่อข้อความ ซึ่งอาจส่งผลให้รอบการจัดกลุ่มข่าวใช้เวลาเพิ่มขึ้นเมื่อมีข่าวเข้าสู่ระบบพร้อมกันจำนวนมาก
    \item \textbf{การแข่งขันในการเขียนข้อมูลของ SQLite}\\*
    แม้ว่าฐานข้อมูล SQLite จะเปิดใช้งานโหมด Write-Ahead Logging (WAL) ซึ่งอนุญาตให้อ่านข้อมูลได้พร้อมกันหลายเธรด แต่การเขียนข้อมูลยังจำกัดให้มีผู้เขียนได้ทีละโพรเซส จึงต้องอาศัยกลไกการล็อกไฟล์ระดับเคอร์เนลเพื่อป้องกันปัญหาฐานข้อมูลถูกล็อกชั่วคราว
\end{enumerate}

\section{ข้อเสนอแนะสำหรับการพัฒนาในอนาคต}
% -----------------------------------------------------------

คณะผู้จัดทำมีข้อเสนอแนะในการพัฒนาโครงงานต่อยอดในอนาคต ดังนี้

\begin{enumerate}[noitemsep,topsep=2pt]
    \item \textbf{การพัฒนาระบบแจ้งเตือนแบบเรียลไทม์ (Real-Time Push Notification)}\\*
    พัฒนาระบบแจ้งเตือนแบบเรียลไทม์ผ่าน Web Push Notification หรือบริการส่งข้อความ เพื่อแจ้งเตือนผู้อ่านทันทีเมื่อมีพัฒนาการใหม่ในประเด็นข่าวที่ผู้อ่านได้บันทึกคั่นหน้าไว้
    \item \textbf{การวิจัยแบบจำลองตรวจจับอคติและจุดยืนของสื่อ (Media Bias and Stance Detection)}\\*
    วิจัยและพัฒนาโมเดลภาษาเพื่อจำแนกจุดยืนทางการเมืองและมุมมองการนำเสนอข่าวของแต่ละสำนักข่าว เพื่อช่วยให้ผู้อ่านได้รับทราบมุมมองที่หลากหลายและเป็นกลาง
\end{enumerate}
